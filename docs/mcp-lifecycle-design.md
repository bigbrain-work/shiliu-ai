# MCP 连接生命周期修复设计（待复核，未实现）

本项单独评审，不与 keyring 超时或 401 识别的发布混合。目标是普通业务失败不使全部工具消失，换令牌不打断在途请求，并统一代理和 shiliu call 的超时、进度、取消及不重放约束。65 秒合成工具只用于防御性验证，不声称现有线上工具已经发生该问题。

## 错误分类与动作

| 输入证据 | 当前请求 | 会话、目录和重试 |
| --- | --- | --- |
| 正常 MCP result，isError=true | 原样转发业务结果 | 保留连接和工具，不重试 |
| JSON-RPC -32601/-32602 | 原样协议错误 | 保留连接；不清空整个目录 |
| 其他 JSON-RPC 错误（含 -32603） | 返回该请求的错误 | 不因单次异常关闭健康传输，不根据消息文字推断401 |
| 确认的 HTTP/SDK 401 | 认证失败，触发一次凭据重读/新连接 | callTool 本次不自动重放；新连接用于后续请求。initialize/list* 等明确幂等发现操作可在同一总截止时间内恢复一次 |
| 请求超时或 caller abort | 返回超时/取消，区分“结果未知” | 不清空工具，不关闭其他在途请求，不自动重放 |
| 明确 transport close/连接中断 | 对受影响请求报告结果未知 | 单例后台重连，保留最后成功目录和可见状态，不重放 callTool |
| keyring不可用、ELOCKED或临时刷新失败 | 状态 CREDENTIAL_UNAVAILABLE | 不清凭据、不提示重新扫码；后续轮询可恢复 |
| 已确认 invalid_grant 且兼容重读失败 | 状态 AUTH_EXPIRED | 要求重新登录，bootstrap工具可用；保留已发现业务目录并在调用时返回明确不可用状态 |

目录只在成功收到完整的新目录后替换；合法的服务端删除通过目录差异反映。不会因为一次失败发出“全部工具删除”再“全部添加”的闪烁通知。错误/超时不表示服务端没有执行或没有计费；没有执行结果时不作零扣费或已取消成功的保证。

## 换令牌与在途请求

引入内部会话代次 generation，包含 client、传输、能力、完整目录及 inFlight 集合。新请求捕获当前代次；令牌变化时先创建新客户端，initialize并取齐目录，成功后原子切换 active。旧代次转为 draining，不再接新请求，等待其已登记请求完成或各自取消/截止后关闭。新连接失败时不主动切断仍健康的旧连接；旧令牌已不可用则按认证状态报告，不重放已有请求。

```mermaid
flowchart LR
  A[旧会话 A 接单] --> B[建立 B 并发现完整目录]
  B --> C[原子切换 active 到 B]
  C --> D[B 接新请求]
  C --> E[A 只完成已有请求]
  E --> F[在途归零后关闭 A]
```

凭据轮询和目录刷新各有 single-flight，代次切换同样去重。代次只是内存编号，不记录令牌或令牌摘要。旧会话通知只作用于其在途请求，不覆盖 active 的目录。服务端 tools/list_changed 在 active 上触发完整分页目录重读，游标重复/分页失败时保留旧快照并报告状态。

## 超时、进度和取消

初始提案：空闲超时120秒，总时长上限15分钟；进度可重置空闲计时，不能突破总截止时间。默认值以实现时复核的 SDK1.32.1 为准；测试可注入短期限，暂不新增 CLI 参数。客户端更早的取消/截止优先。两个默认值是评审点，可按产品任务SLA调整。

代理把 request extra.signal 传给远端请求。SDK Client.callTool 的 options 在第三个参数位（第二位是 resultSchema），需要明确适配，不能对所有方法机械传第二参数。其他方法按对应SDK签名传入相同请求上下文。

只有上游请求提供 progressToken 时才向该调用者转发 progress；远端由SDK分配的进度令牌映射回上游令牌，只转发progress/total/message等字段，不能串到其他请求或其他代次。onprogress 的通知失败不造成业务重放。取消使用SDK的取消通知/AbortSignal，不能关闭整条共享传输。

shiliu call 使用同一截止时间、取消和不重放实现；Ctrl+C 取消当前调用，stdout 仍为单份业务JSON。进度先用于更新空闲期限，不新增默认stderr进度输出，以免改变JSON错误契约。需要可视进度时另行明确产品接口。

## 发现、恢复和关闭

远端初始发现和 list_changed 都读取全部 tools/list 页；检测重复游标并设分页上限。未支持的方法错误保留原有协议语义。后台重连只负责连接/发现，采用有上限的退避及单例调度，不重新执行用户业务请求。

stdin end/close、server close、SIGINT/SIGTERM 进入同一个幂等 shutdown：停轮询、停止新请求、取消本进程在途等待、关闭全部代次并清理监听器。关闭应有界，不能因远端无响应永久保留本地进程。是否需要额外传输销毁，以 SDK 真实行为测试决定；不得无依据增加全局强制 exit。

## 验证矩阵与发布门槛

1. 单个 isError、-32602、-32603、含401业务文字均不清目录，不二次执行业务；明确HTTP401只恢复连接，不重放callTool。
2. 请求A在旧令牌会话运行，切换后请求B走新会话，A仍成功；新连接失败、取消、超时以及并发轮询均无重复关闭/切换。
3. 本地合成65秒工具真实跑一次，验证默认不会60秒失败；带进度/不带进度、空闲超时和总上限由缩时测试覆盖，不调用生产付费工具。
4. progressToken与取消按请求/代次隔离；并发两次调用，取消一个不影响另一个。远端收到取消也不声称业务已经回滚。
5. 两页工具发现、目录变化、重复游标、分页中断；只有完整成功快照触发准确list_changed。
6. stdin EOF、中途断开、信号关闭及Windows标准cmd/npx包装场景；记录实际PID退出、资源释放和远端执行次数。
7. 代理与 shiliu call 共用上述行为；CLI JSON stdout、错误JSON、退出码和原生客户端发现保持兼容。至少一个真实客户端重连和免费余额验收。

实现前需要用户复核本设计，重点是120秒/15分钟默认期限、callTool包括401在内不自动重放、认证失败时保留目录的展示策略。获准后独立分支、PR、测试和版本发布；未获复核前仅可提交此设计文档。
