# 本批 PR 合入后的 P2 计划

本文件仅规划，不表示已经修复或获准在本批开发。CLI P1 PR 与后端播放量 MR 合入后，从各自最新 main 新建或复用适合的新任务分支；不处理原目录的无关未提交文件。各项分别交付，避免把生命周期重构夹进错误格式的小修复。

| 顺序 | 范围及设计边界 | 完成证据 |
| --- | --- | --- |
| 1 | 恢复参数解析的原始错误及现有 formatCliError JSON 契约；按解析出的命令识别 MCP，禁止以 includes(mcp/proxy) 判断参数值 | 真实入口运行 --bogus、login --json --session bad、--agent mcp 等；保留具体信息/退出码/JSON，stdout 不混诊断日志；MCP 致命配置错误仍正确分类 |
| 2 | keyring 子进程有界等待、错误/退出/超时只完成一次，关闭 stdin、终止明确的 worker 并清理定时器；不清凭据、不提示重新扫码；锁释放和同进程 refresh 去重联动 | 卡住 worker、半包 JSON、提前退出、并发 error/close；代理报 CREDENTIAL_UNAVAILABLE、无凭据泄露；释放锁后其他进程可恢复 |
| 3 | 401 基于明确 HTTP/SDK 认证状态和精确认证错误码，不从任意业务文本推断；已开始的非幂等调用不因文字含 401/token invalid 自动重放 | 业务结果及 JSON-RPC 错误含 401、订单号/文案含 token invalid 均不二次执行；真实未授权恢复仍受限；调用次数是验收主证据 |
| 4 | 连接生命周期整体设计：区分业务/协议/传输错误；令牌变化以新会话接替，旧会话排空在途请求；统一 call 与代理的截止时间、取消和进度上下文，明确总超时及不重放约束 | 单个业务失败不清空工具；换令牌过程中在途调用完成；>60s 合成工具、带进度/无进度、调用者取消和断线；远端执行次数、取消收到情况和代理通知均实测 |
| 5 | repair 锁结合持有进程与过期状态处理；PowerShell 5.1 输出显式 UTF-8，识别中文用户名下的真实进程；不误改正在使用的 npm 缓存 | 活进程锁不抢占、已退出锁可恢复；中文路径在 PS5.1/PS7 下匹配同一 PID；只针对已核实缓存项操作，恢复失败保持可诊断 |

第 4 项的 60 秒测试是防御性验收，不据此声称现有某工具已出现生产超时。需要从现有工具和日志补现实耗时证据；不为测试重复提交付费任务。stdin EOF 和包装进程退出仍作为条件场景检查，不把单个夹具行为推广为所有生产客户端问题。

每项记录问题触发、兼容契约、实际结果和剩余限制。SDK 本批已升级，后续实现以合入后的实际版本为准，不能重新依赖旧 SDK 行为假设。
