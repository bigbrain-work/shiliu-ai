# Shiliu AI: Agent installation guide

Canonical URL: https://bigbrain.work/shiliuAI/install.txt

Use this guide only for a user-authorized installation. Follow Steps 1-6 and resume at the failed stage after repair. Do not infer installation steps from the product homepage. Never request credentials or place tokens in commands, code, Git, Agent configuration, logs, or replies. The CLI owns credential storage.

## 1. Check the environment

Identify the current Agent, shell, and runtime that will launch MCP. The CLI and MCP process must share the same OS user and credential store. If the client cannot launch local stdio servers, report the limitation before installing.

For Skill scope, use the requested scope. Otherwise use a persistent project root, or user scope if no project exists. Avoid temporary directories.

Run one command per invocation and check each exit code:

```text
node --version
npm --version
```

Require Node.js 18 or newer. If Node/npm is missing or Node is too old, use the official Node.js 22 installer at https://nodejs.org/en/download, reopen the terminal, and recheck. The installers below upgrade npm versions older than 8 to npm 9.9.4. Preserve the current PATH; shell changes may not persist between Agent commands.

## 2. Install CLI

Choose exactly one matching installer.

macOS/Linux or Windows Git Bash:

```sh
curl -fsSL https://bigbrain.work/shiliuAI/install.sh | sh
```

Windows PowerShell:

```powershell
irm https://bigbrain.work/shiliuAI/install.ps1 | iex
```

Require the installer's `CLI installed.` message and verify separately:

```text
shiliu --version
```

Require CLI 1.3.7 or newer. If `shiliu` is blocked by PowerShell execution policy, use `shiliu.cmd` in that PowerShell session. If the command is missing, resolve the npm global executable location without replacing the runtime's PATH. CLI installation alone does not complete MCP setup.

## 3. Install Skill

Select only the current client. Skill installer identifiers and Shiliu CLI identifiers are not always the same:

| Client | SKILL_AGENT | MCP_AGENT |
| --- | --- | --- |
| Codex | codex | codex |
| Claude Code | claude-code | claude |
| Cursor | cursor | cursor |

Install the Skill with the matching `SKILL_AGENT`:

```text
npx -y skills add https://bigbrain.work/shiliuAI --skill shiliu-ai-mcp -a SKILL_AGENT -y
```

Add `-g` for user scope; otherwise run from the chosen project root. This website source needs neither Git nor GitHub. Record the installed Skill path and confirm the client can discover it.

If the skills CLI does not support the current client, use that client's documented Skill import mechanism when available; do not guess an identifier. A Skill failure does not prevent MCP authorization when the client can still launch local stdio MCP servers. Continue in that case and report the Skill as unavailable. If the client supports neither Skills nor local stdio MCP, stop and report the limitation.

## 4. Authenticate with WeChat

Run `shiliu status`. Reuse working authentication. Log in only when credentials are absent or explicitly rejected; a network failure alone does not justify logout.

```text
shiliu login --no-wait --json
```

Read `qr_code_path`, `qr_code_mime_type`, `user_code`, `poll_command`, `poll_after_seconds`, and `expires_in`. Poll responses may also include `authorization_stage` as `waiting_for_scan` or `processing_callback`. Display the existing local PNG through the current client's human-visible image capability. Agent-side image reading does not prove that the user can see it. Do not recreate or upload the QR, and do not open `verification_uri` as a normal webpage.

Tell the user only: use WeChat to scan the displayed QR code. There is no confirmation button on the phone. Do not wait for the user to reply that scanning is complete.

Immediately run the exact returned `poll_command`. It is a single-shot command. If it returns `authorization_pending`, wait `poll_after_seconds` and run the returned command again. Continue until success, rejection, expiry, a non-retryable error, or the reported `expires_in` reaches zero. Do not use the blocking `--wait` mode in the Agent installation flow. Give the user a progress update at least once per minute.

Track one active login session. Re-running `login --no-wait` must reuse an unexpired local session; do not create duplicate pollers or display an older QR image.

| JSON status | Action |
| --- | --- |
| `success` | Continue to Step 5. |
| `authorization_pending` | Wait the returned interval and poll the same session again. |
| `slow_down` | Use the increased interval and poll the same session again. |
| `expired` | End this session; create at most one replacement and clearly identify its new image. Stop if it also expires. |
| `rejected` | Stop authorization and report rejection. |
| `network_error` | Report the network failure without credentials; do not infer success or replace the session automatically. |
| `error` | Report the returned error and stop unless its action is explicitly recoverable. |

Pending does not prove a callback fault. Deleting a PNG does not revoke its server session.

## 5. Configure the current Agent

Use the `MCP_AGENT` value from the mapping table:

```text
shiliu install --agent MCP_AGENT --json
```

Configure only the current client. Built-in adapters support Codex, Claude Code, and Cursor. For another safe name, the CLI may return `configuration_generated` with credential-free stdio configuration; `generated_only` means it was not written into the client.

Inspect `configuration_state`, `config_path`, and `reload_required`. Preserve unrelated settings. Reload or reconnect the client when required. Do not report Agent access while configuration is only generated or while a required reload is pending.

On Windows, keep the generated `cmd /d /s /c npx ... mcp` stdio definition. Do not replace it with `shiliu.ps1 mcp`; npm's PowerShell wrapper may buffer piped input and is not a reliable duplex MCP transport.

## 6. Verify and report

Run separately:

```text
shiliu status
shiliu tools
```

Require authenticated CLI connectivity and a successful live `tools/list`. Also confirm that the current Agent has loaded its MCP connection and can discover the live tools. Do not assume a fixed tool count or run billable business tools solely for installation testing.

Report the CLI version, Skill path and scope, configuration state and location, reload state, CLI connection result, Agent connection result, and discovered tool names. Distinguish `CLI ready`, `configured but awaiting reload`, and `Agent connected`. If Agent discovery cannot be verified, say so. Continue the original task using only capabilities actually available.

For an existing connection failure, use the installed Skill's `references/installation.md`. Update policy belongs to `SKILL.md`, not an extra installation stage. Do not use logout or an unscoped Skills update as generic troubleshooting.
